# 系统差异

GPM 可以在多个操作系统上运行，但部分进程管理功能依赖操作系统提供的能力。将同一份进程配置迁移到其他平台前，请先了解以下差异。

[English](../Platform-Differences)

## cgroup 资源限制

GPM 基于 cgroup 的 CPU 和内存限制仅在 Linux 上可用。

- Linux 主机需要提供可用的 cgroup v1 或 cgroup v2 环境，运行 GPM 的账户也需要具备创建和管理 cgroup 的权限。
- 如果系统不支持 cgroup 或初始化失败，受管进程仍会启动，但配置的 CPU 和内存限制不会生效。具体原因可查看 GPM 日志。
- 在 Windows 和其他非 Linux 系统上，为进程启用 cgroup 不会生效。

## 停止进程

普通“停止”操作在不同平台上的行为如下：

| 平台 | 行为 |
| --- | --- |
| Linux | GPM 先发送 `SIGINT`，并等待配置的停止等待时间；进程未退出时，再执行强制终止。 |
| Windows | Go 的 `os.Process.Signal` 无法在 Windows 上发送 `SIGINT`，因此 GPM 会立即转入内部的强制停止（`Kill9`）流程，不会等待配置的停止等待时间。 |

`Kill9` 是 GPM 对“立即强制停止”流程的内部命名。在类 Unix 系统上，它对应 `SIGKILL` 等强制终止方式；在 Windows 上，Go 使用 Windows 的 `TerminateProcess` API 终止进程，并不存在字面意义上的 `kill -9` 信号。

如果应用需要优雅退出，应提供适合目标平台的独立关闭机制，尤其是在 Windows 上由 GPM 管理时。
