# 事件记录

GPM 会将重要的进程、任务、API 和推送活动记录为系统事件。事件可用于审计操作人、确认进程状态变化时间，以及关联同一次任务执行的开始与结束记录。

[English](../Events-and-Retention)

## 查看和筛选事件

管理员可以在“系统事件”页面查看事件时间、类型、名称、用户和附加信息，并按时间范围、事件类型、名称、用户及附加键值进行筛选。

事件保存在 [`~/.gpm/data.db`](../Log-Storage-and-Search) 的 `event` 表中，不受进程日志存储方式影响。

## 事件记录场景

| 事件类型 | 记录时机 | 附加信息 |
| --- | --- | --- |
| `ProcessStart` | 受管进程进入运行状态时，包括自动重启。 | 重启次数。 |
| `ProcessStop` | 受管进程完成退出时，包括主动停止和意外退出。 | 进程启动时间和停止耗时。 |
| `ProcessWarning` | 受管进程进入警告状态时，例如启动失败或达到自动重启次数上限。 | 可用时记录警告原因和进程启动时间。 |
| `ProcessConnect` | 用户或共享终端连接接入受管进程时。 | 事件用户用于标识该连接。 |
| `TaskStart` | 一次任务执行开始时，包括手动、定时、API Key 或进程状态触发。 | 跟踪 ID。 |
| `TaskStop` | 一次任务执行结束时。 | 跟踪 ID、成功标记和执行耗时。 |
| `ApiRequest` | 已认证的 `POST`、`PUT` 或 `DELETE` 请求结束时；成功和失败的修改请求都会记录。 | 请求 URI、请求方法和响应状态。 |
| `PushRequest` | GPM 尝试执行一条已启用的外部推送请求时。 | 替换后的变量，以及 HTTP 状态码或请求构造、传输错误。 |

只读 `GET` 请求不会记录为 `ApiRequest` 事件。一次操作可能产生多条事件，例如通过 API 启动进程时，可能同时产生 `ApiRequest` 和 `ProcessStart` 事件。

## 定时清理

`EventStorageTime` 设置控制事件保留天数，默认值为 `30`。

- GPM 启动时，如果 `EventStorageTime` 大于或等于 `0`，会创建事件清理任务。
- 清理任务每天按 GPM 所在主机的本地时间在 `03:00` 执行。
- 每次清理会删除创建时间早于“当前时间减去保留天数”的事件。
- GPM 启动时将该值设为负数，可禁用定时清理。
- 设为 `0` 时，会删除早于本次清理时刻的事件，效果相当于每天清空已有事件历史。

修改 `EventStorageTime` 后应重启 GPM，尤其是在启用或禁用清理时，以保证清理任务与已保存的设置一致。清理不会在启动或修改设置后立即执行，新的保留阈值会在下一个定时时间生效。已删除的事件只能通过 `data.db` 备份恢复。
