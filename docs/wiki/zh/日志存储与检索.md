# 日志存储与检索

GPM 会收集受管进程的输出，供你在管理界面中检索。

## 本地存储路径

默认情况下，GPM 将本地数据存放在 `~/.gpm` 中。这里的 `~` 是运行 GPM 的操作系统用户的主目录。如果 GPM 以系统服务运行，应查看服务账户的主目录，而不是访问管理界面的用户的主目录。

| 路径 | 类型 | 用途 |
| --- | --- | --- |
| `~/.gpm/config.json` | 文件 | 保存 GPM 配置；配置文件不存在时，GPM 会使用默认值创建该文件。 |
| `~/.gpm/data.db` | 文件 | 保存进程、用户、权限、任务和事件等 GPM 数据；选择 SQLite 日志存储时，进程日志也保存在这里。 |
| `~/.gpm/log.bleve` | 目录 | 选择 Bleve 日志存储时，保存本地全文检索索引。 |
| `~/.gpm/log.diskqueue` | 目录 | 在进程日志写入所选日志存储前，将待处理日志暂存在磁盘中。 |

备份这些内容前应先停止 GPM，以保持数据库、索引和待处理日志队列的一致性。只有使用过 Bleve 日志存储后，才会出现 `log.bleve` 目录。

## 选择存储方式

| 方式 | 适合场景 | 使用注意 |
| --- | --- | --- |
| SQLite | 小规模部署和简单的本机运行。 | 不需要额外服务。 |
| Elasticsearch | 较大规模或需要集中检索日志的场景。 | 需要运行 Elasticsearch 并持续管理容量。 |
| Bleve | 希望在本机进行全文检索，但不想部署额外服务。 | 会占用本地磁盘，应纳入备份。 |

请按日志量和运维方式选择。切换存储方式不会自动搬迁历史日志，变更前请做好保留和备份计划。

## 检索日志

在日志搜索框输入一个或多个词：

- 用空格分隔多个词，表示结果需要同时满足它们。
- 用双引号包住短语，例如 `"out of memory"`。
- 在词前加 `~`，可查找作为更长消息一部分的内容。
- 在词前加 `!`，可排除包含该词的消息。

示例：

```text
error timeout
"out of memory"
~GET /api
error !debug
```

不同存储方式对全文、局部词和高亮的处理可能略有差别。用于告警的重要查询，请先用接近生产环境的日志验证。
