# 任务自动化

任务可让 GPM 自动执行进程操作。你可以按计划运行任务、把多个任务串成流程、在进程状态变化时触发任务，或从外部工作流调用任务。

## 创建任务

创建任务时，选择：

- 用于判断状态的进程；
- 需要启动或停止的进程；
- 执行操作前必须满足的条件；
- 操作是立即继续，还是等待完成。

任务可以启动已停止的进程、停止正在运行的进程，或等待所选操作完成。同一个任务正在执行时，不会被重复启动。

## 定时任务

启用定时计划并填写 Cron 表达式。GPM 支持标准五段计划，也支持包含秒的计划。

示例：

```text
# 每天 03:30
30 3 * * *

# 每 10 秒
*/10 * * * * *
```

想暂停自动执行时，请禁用定时计划。新计划应先在无风险进程上测试。

## 任务流

把多个任务按顺序连接，可形成简单工作流：

```text
准备服务 → 启动服务 → 执行后续检查
```

只有上一步成功后，下一步才会运行。每个任务应专注于一个操作，避免循环引用，并尽量让每一步可以安全重试。

## 进程状态触发

可以在另一个进程启动、停止、进入警告状态或发生其他被监控的状态变化时启动任务。

这适合恢复操作、后续作业或协调服务启动。状态触发任务即使定时计划已暂停也可能运行，因此应先充分测试。

## 从外部工作流触发

需要集成外部系统时，在任务设置中启用 API 触发并生成触发密钥。然后在自动化系统中使用 GPM 提供的受保护触发链接。

触发链接应像密码一样保护，不要暴露在公共日志、浏览器历史或群聊消息中。API 触发会在后台启动任务；请通过任务活动和事件确认是否完成。

## 手工运行与排障

管理员可在 Web 界面或命令行查看、启动和停止任务：

```bash
gpm task list
gpm task start 12
gpm task stop 12
```

排障时，请检查任务是否正在运行、最近事件、目标进程状态和受影响进程的日志。
