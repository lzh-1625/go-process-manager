# 角色与权限

GPM 使用角色控制管理功能，并使用逐进程访问控制满足日常使用需要。

## 角色

| 角色 | 常见用途 |
| --- | --- |
| Root | 完整的系统管理，包括设置、用户、权限和进程配置。 |
| Admin | 日常运维，包括任务、通知、事件、指标和终端分享。 |
| User | 只能访问管理员明确分配的进程和日志。 |
| Guest | 访问能力非常有限。 |

日常运维建议使用 admin；涉及安全和系统级修改时再使用 root。

## 进程访问

管理员可以按进程决定用户是否能够：

- 查看进程；
- 启动或停止进程；
- 打开进程终端；
- 在终端中输入；
- 查看历史日志。

请按最小权限原则分配。例如，支持人员可能只需要查看日志和只读终端，不需要停止进程的权限。

## 管理建议

- 团队成员或服务负责人变更后，及时检查访问权限。
- 不再需要时撤销终端分享链接。
- 不要共享管理员账户，为每位成员创建独立账户。
- 把权限交给用户前，先用非管理员账户进行验证。
